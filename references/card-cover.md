# 卡片封面（纯色封面）投递清单

> 一句话：封面不是「塞进 `MediaMetadata` 就完事」。系统卡片 / 原子组件 / 车联是**另一个进程按 URL 自己下载图片**，约束和 App 内渲染完全不同。这条链上任何一环坏了，表现都一样：**纯色封面**（组件取封面主色填满）。2026-10-24 `kgka_Music_hl`（Flutter + audio_service，酷狗 + 网易云双源）实机录屏逐条定位，下面 8 条全踩了一遍。

## 症状长什么样

- 切歌后封面变成一块纯色（歌名、歌词都正常）。
- 有的歌正常、有的歌纯色（**跟数据相关，不是概率**，所以别当"时好时坏"处理）。
- 首曲正常，切几首之后一直纯色。
- **App 内播放页封面正常，卡片纯色** ← 这是关键判据：说明问题在「投递」或「卡片侧拉图」，**不在取图**。

## 8 条坑（按排查顺序）

### 1. `content://` / `file://` 拉不到

卡片侧只认 http(s)。本地歌曲 `content://media/...`、App 私有目录 `file:///data/user/0/...` 一律拉不到。
不要投坏地址：归一化函数直接返回 `null`，组件退化成占位图，至少不会显示错图或纯色。

### 2. URL 里的**字面量占位符**没替换（最常见的 404 源）

酷狗 `http://imge.kugou.com/stdmusic/{size}/2026xxxx/xxx.jpg` 里的 `{size}` 是**模板占位符**，原样请求返回 **404**；
实测（真机网络直连）：`{size}` 原样 → 404；`/120|240|400|480|800|960|1024/` 实体目录 → 全部 200。

```dart
if (url.contains('{size}')) return url.replaceAll('{size}', '480');
```

> ⚠️ 这个 404 **不会出现在我们自己 App 的日志里** —— 是卡片进程在拉图。所以「App 日志一片干净 + 卡片纯色」完全可能是 URL 坏了。

### 3. `http://` vs `https://`：按实测定，别照抄别人的结论

同一个仓库里两个项目结论是**相反的**：

| 项目 | 组件/环境 | 结论 |
|---|---|---|
| NeriPlayer | kugou 源 + 老版原子组件 | 只吃 `http://`，换成 https 反而不显示 |
| kgka_Music_hl | 2026-10 版 vivo 组件 | `http://` 被拦，**必须** https |

说明这条随组件版本变化，也会受 App 自身 `networkSecurityConfig` 影响。判据：**卡片进程自己下载，不受我们 App 的明文配置保护**。
默认走 `https://`（更安全），投递日志里把最终 URL 记下来；若改成 https 后突然纯色，就退回 http 验证——两种都试过才能下定论。

### 4. 大图下载超时 → 同样纯色

原图常有 1~2 MB，卡片侧下载有超时限制。投 480px 级别的图：

- 网易云：`?param=480y480`（`sized()` 里按 2 倍逻辑像素取值，夹在 120~1024 之间）
- 酷狗：`{size}` → 480

实测「**部分歌曲纯色**」最常见的成因就是这个（小封面没事，大封面超时）。

### 5. 数据源根本没给封面

酷狗**搜索接口不返回封面**（`imgurl` 全为 `None`），如果只投 `song.coverUrl`，这类歌**永久纯色**。要按专辑补：

```
http://mobilecdnbj.kugou.com/api/v3/album/info?albumid=...   → data.imgurl（带 {size} 模板，见坑 2）
```

网易云走 `.../song/detail`（`album.picUrl`）。酷狗 `v3/song/detail` 形状不稳定（返回非 JSON），别走那条。

> 通用原则：封面地址**可能来自异步补取**。App 内显示封面时会补，投给卡片的地址必须同样走补取结果，不能直接读原始字段（原始字段经常是空）。

### 6. 负缓存不能「永久」

`取不到 → 永久不再重试` 会把一次网络抖动放大成「这首歌整场会话没封面」，卡片一直纯色。
改成带 TTL 的负缓存（1 分钟）+ 支持强制重试一次，歌词/元数据重推时顺带再试。

### 7. 空串 ≠ 清空

歌词刷新会推很多次（整段 LRC、翻译、罗马音各一次）。如果「本次没带封面」就把**已投递**的封面设成 `null`，卡片会**闪回纯色**。
规则：**非空才覆盖**，真正的清空只发生在换曲（`loadSong` / `setSongQueue`）。

### 8. `audio_service` / media3 的整份替换

`audio_service` 每次 `mediaItem.add()` 都会 `MediaSessionCompat.setMetadata()` **整份替换**（实测 audio_service-0.18.19 `AudioService.java:786-804`）。
只在原生通道注入协议字段，任何一次逐行歌词 / 蓝牙 / 队列更新都会把它抹掉。

做法：
- 把 `ucar.media.metadata.*` / `vivomusicmix.*` 放进 `MediaItem.extras`，让 audio_service 自己写回去。
- `support_event = 31` 要在**首个** MediaItem 就带上：组件在**绑定那一刻**读一次能力位，之后再补常常不回来（实机症状：原子通知无歌词、无进度条）。

## 归一化：所有封面地址走同一个出口

```dart
/// 投给系统媒体卡片 / vivo 原子组件的封面地址。
static String? cardUrl(String? url, {double size = 480}) {
  final raw = url?.trim() ?? '';
  if (raw.isEmpty) return null;                                        // 坑 5/6：没有就算了
  if (!raw.startsWith('http://') && !raw.startsWith('https://')) return null; // 坑 1
  final bounded = sized(raw, size) ?? raw;                             // 坑 2 + 坑 4
  final https = bounded.startsWith('http://')                          // 坑 3（按实测可回退）
      ? 'https://${bounded.substring(7)}'
      : bounded;
  return Uri.tryParse(https)?.toString() ?? https;                     // 转义中文/空格，卡片下载器很敏感
}
```

单点归一的价值：**单点日志**。所有投出去的封面地址只有一个来源，出问题不用满仓库找。

## 诊断：日志要能分层

一处投递日志，至少四个字段：`songId / 原始地址 / 归一后地址 / 是否为空`。

| 现象 | 指向 |
|---|---|
| 原始有、归一后为空 | 坑 1 / 坑 2 |
| 归一后有、卡片仍纯色 | 坑 3 / 坑 4 |
| 原始就为空 | 坑 5 / 坑 6 |
| 先有封面、几秒后变纯色 | 坑 7 |
| 有歌名、无歌词无进度条 | 坑 8 |

只 `print(地址)` 而不分层，会把「空地址」和「坏地址」混成一团，最后误判成协议问题、白改一版。

## 别做的事

- 不要把 App 内用的大图直接投给卡片（坑 4）。
- 不要用「永久负缓存」换性能（坑 6）。
- 不要在歌词刷新时顺手清封面（坑 7）。
- 不要因为 App 内封面正常就断定协议没问题 —— **两个进程，两套约束**。
- 不要因为「歌词已经通了」就以为封面也通了 —— 封面和歌词是两条独立链路，可以一条好一条坏。
